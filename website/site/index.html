How it works

Five ideas, drawn simply.

Each idea in plain words first. Then what is underneath, for the engineers.

01Thread-per-core

Every key has exactly one owner.

InfinityDB gives each CPU core its own slice of your data, its own network loop and its own memory. Nothing is shared, so nothing waits on a lock, and every request knows exactly where it has to go.

Under the hood

One pinned thread per core. owner(key) = slot_to_cell[crc16(hashtag(key)) % 16384], the same 16,384 slots as Redis Cluster, so hash tags like {user:42} keep related keys together.

L1 · One core, one shard, one owner
02The fabric

Cores talk in batches, not interruptions.

When a request needs data another core owns, it sends a message down a private lane between the two. Messages are grouped and delivered once per loop, so the busier the system gets, the cheaper each message becomes.

Under the hood

A full mesh of lock-free single-producer, single-consumer rings. One doorbell per batch, never per message. Credit-based flow control pushes back on the client instead of growing a queue.

L3 · Batch every boundary
03The log spine

The log is the database.

Every durable change is first an append to a per-core log. A cache is that log switched off. A durable store is the log plus an index. A queue is the log read forward. One mechanism, made correct once.

Under the hood

Per-cell segments with CRC32C batch frames. Group commit: one write per loop iteration. Fuzzy checkpoints in bounded slices, with no fork() and no stop-the-world.

L2 · The log is the database
04Deterministic simulation

Every failure is a seed.

The whole database can run inside a simulator where time and chance are controlled. We cut power, tear writes and reorder messages on purpose. When something breaks, one number replays it exactly.

Under the hood

Time, randomness and I/O are injected. Simulated disks lose, tear and reorder unsynced writes. Invariant oracles run continuously, and a nightly fleet runs fresh seeds.

L7 · Determinism is a feature
05Redis-compatible

Keep your clients. Upgrade your guarantees.

InfinityDB speaks the Redis protocol, so redis-cli and the SDKs you already use simply connect. Then, one namespace at a time, turn on durability, store JSON documents, and pick up queues and vectors as they land.

Under the hood

RESP2 and RESP3 on port 6379. A generated compatibility matrix marks every command full, partial, stub or absent. Behaviour differences are documented, never silent.

L8 · Compatibility is staged, honesty is total
Roadmap

Built in the open, gate by gate.

Every milestone ends in STOP gates. If one fails, feature work halts until the architecture is fixed, not patched later. We are an alpha, and we say so.

Hot records gather at the tail, in memory. Untouched records drift toward disk. No separate LRU: the shape of the log does the sorting.

Design laws

Thirteen laws. Changed only by amendment.

Every design decision cites one. Code follows InfinityStyle, adapted from TigerBeetle's TIGER_STYLE: safety, performance and developer experience, in that order.

L1
One core, one owner.
One shard per core. No data-plane locks, no shared mutable state.
L2
The log is the database.
Every durable fact is an append first. Indexes are rebuildable.
L3
Batch every boundary.
Syscalls, hops and fsyncs are paid per batch, never per operation.
L4
Measured, not assumed.
Every hot-path trick ships with a reproducible A/B, or behind a flag.
L5
Memory is the product.
Compact variable-size records. Every byte attributed to a named domain.
L6
Commands are resumable.
Disk, fabric and fsync waits suspend a command, never the core.
L7
Determinism is a feature.
Same input, same state, same log, byte for byte.
L8
Compatibility is staged.
Honesty is total: every command marked in a public, generated matrix.
L9
Safety is layered.
unsafe lives in audited leaf crates, and every decoder is fuzzed.
L10
Claims follow evidence.
No public number without replicates, a clean tree and the rival in the run.
L11
Extend by seam, not fork.
Engines attach through versioned seams. First-party code gets no shortcut.
L12
Design before code.
Nothing is built until a reviewed record proves the design.
L13
One decision, one place.
Enforced by a type, a lint or a generated table before a reviewer.

Evidence

Claims follow evidence.

We don't publish a performance number until it has been reproduced on the reference box: three to five replicates, a clean tree, and the system we compare against running in the same campaign. Until then, the ledger says pending.

This site contains no benchmark numbers. That is deliberate.

Moss, the moss piglet. Tardigrades survive boiling, freezing and vacuum. Moss survives torn writes, lying fsyncs and power cuts, in simulation, every night. Eight legs, eight cells.
