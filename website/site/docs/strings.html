      Strings & keys

      The string, key, expiry, pub/sub and server families are the cache core. Their corpus cases are compared with Redis 8.0.5, and the compatibility matrix lists the deviations recorded for each command.

      Available · alphaLaw L8

      Slots and hash tags

      A key maps to one of 16,384 slots with the function Redis Cluster uses: CRC16 of the key, or of its {hash tag} if it has one. Each cell owns a contiguous range of slots, so session:{u42} and visits:{u42} above live on the same cell. On a numbered database a multi-key command across cells still works and pays a fabric hop; on a named namespace its keys must share a cell (JSON.MGET excepted), so give them one tag. The cell count is recorded in the data directory at first boot, and a boot with a different --cells is refused.

      Expiry

      Each store keeps a hierarchical timing wheel: four tiers of 512 slots at 1 ms, 512 ms, about 4.4 minutes and about 37 hours per slot, about 2.2 years in all, with an overflow list beyond. A key with a deadline holds exactly one 16-byte wheel node. Active expiry runs in background slices of at most 4,096 expirations, rotated across databases so that one expiry storm cannot starve the others, and an expired key is also removed lazily when read. A mass expiry therefore drains in bounded slices instead of one long pause.

      Durable namespaces log absolute Unix-millisecond deadlines, so a restart keeps the right expiry times. A deadline about 34.8 years or more ahead clamps to the record's 40-bit bound, and TTL then reports that bound. DEBUG SET-ACTIVE-EXPIRE is accepted and ignored: the wheel stays on.

      SCAN and whole-keyspace commands

      DBSIZE, KEYS, SCAN, RANDOMKEY, FLUSHDB and FLUSHALL go to every cell. A SCAN cursor carries the cell number in its top 16 bits and that cell's own cursor below; treat it as opaque. Each cell's walk returns every key present for the whole scan at least once, even while its table grows. KEYS order is engine-defined, DBSIZE is exact, and FLUSHALL is atomic per cell and completes across cells within one round, with no global pause.

      Pub/sub

      A channel is owned by the cell that owns its slot; subscriber state lives on the subscriber's own cell. PUBLISH goes to the owner, which sends one fabric message per cell that has subscribers, not one per subscriber. A SUBSCRIBE is confirmed only after the owner knows about it, so once you see the confirmation, a PUBLISH from any cell reaches you. RESP3 connections receive push frames. client-output-buffer-limit disconnects a subscriber that falls too far behind: 32 MiB hard, or 8 MiB for 60 seconds, by default. Sharded pub/sub and keyspace notifications arrive in M5.

      Value in one record16 MiB − 1 bytethe same typed error; nothing changes
      Bulk string (proto-max-bulk-len)16 MiB by default, at least 1 MiB (Redis: 512 MiB)protocol error; the connection closes
      Whole request / argumentsbulk cap + 64 KiB / 1,024protocol error; the connection closes
      Durable recordone log staging buffer, 4 MiB − 56 bytes by defaultERR write exceeds durable log staging capacity

      On a single-cell, non-tiered path MSET checks the bounds of every pair before it writes any, so there a bounds error means nothing changed. A cross-cell MSET skips that check: it applies each local pair whose write succeeds and, when none failed, sends each remote pair to its owner, which applies or refuses it on its own. A tiered one applies pair by pair and stops at the first error. So either can answer an error after applying some of the pairs (on a tiered namespace, a prefix). Instead of one record, tiered namespaces route values at or above BLOB-THRESHOLD out of line; see Beyond RAM.

      Databases and namespaces

      SELECT 0 to 15 work as in Redis. They are memory namespaces: always memory-only, even on a node with a data directory, and they share the node's maxmemory. Durability, per-namespace budgets and tiering belong to named namespaces created with INF.NS CREATE on a node started with --data-dir; INF.NS USE name binds a connection to one, and INF.NS USE db3 is the same as SELECT 3. On a named namespace, FLUSHDB and COPY are refused, and FLUSHALL is refused on any node that has a durable namespace. See Namespaces & durability.

      L8
      Compatibility is staged and honest.

      Compatibility is declared per command, in a matrix generated from the command table and a corpus diffed against real Redis. CI fails when the matrix is stale or a corpus reply differs from Redis with no recorded deviation for the case.
