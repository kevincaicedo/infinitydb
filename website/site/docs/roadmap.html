Reference

The milestone train

InfinityDB ships on a release train with STOP gates: every milestone ends with hard, numeric, end-to-end acceptance criteria measured on a designated reference box, and a milestone that fails its gate halts feature work — the fix happens at the architecture layer, not as an optimization pass later. Every milestone is an independently shippable product.

How to read this page: statuses are honest. “Done” means the milestone’s verdict was reached with its evidence recorded; durations are estimates from the plan, not promises; and none of the numeric gate targets are reproduced here, because targets are not achievements — the project’s claim ledger governs which numbers may be published. The authoritative document is docs/infinity-master-plan.md §21–22.
The train was reordered — by ADR, in the open. ADR-0023 (2026-07-05) reordered the train documents-first and renumbered it (JSON documents moved from sixth position to M3; tiered storage to M4; the collection types to M5; transactions to M6; streams to M7), and inserted M2.5 “Hardening & First Alpha.” ADR-0024 inserted M4.5 “Indexes & Query” — typed secondary indexes plus a planner-free PartiQL subset, pre-1.0. ADR-0025 restructured M2.5 performance-first: the first public tag carries the paid performance debt. ADR-0048 (2026-07-16) retired v0.2.0-alpha.1 unused and moved the first public tag to M3’s v0.3.0-alpha.1 — M2.5’s release act folded into M3 rather than shipping an alpha the project would immediately supersede. Documents dated before 2026-07-05 use the old numbering.

Done

M0 — Skeleton: proof of architecture DONE · VERDICT, NO RELEASE

The single most important milestone, and deliberately feature-free: an end-to-end vertical — cell loop on io_uring, the SPSC fabric, the SIMD RESP wire, a minimal store, the benchmark harness with tripwire metrics, and the deterministic simulator’s walking skeleton — measured against hard gates before any feature work was allowed to exist. The predecessor project died because this step never existed. One gate (pipelined node throughput at the spec’d cell count) remains formally open, dispositioned by ADR-0029 and carried into M2.5’s performance work rather than silently narrowed.

M1 — Cache core DONE

The full string/key/expiry/server command surface, per-cell TTL wheel with budgeted active expiry, all 8 eviction policies, namespaces v1, pub/sub with RESP3 push, the generated compatibility matrix with its CI staleness gate, oracle byte-diffing against a pinned Redis 8.0.5, Docker/CI release engineering, and the nightly deterministic-simulation fleet. v0.1.0-alpha.1 was never tagged, and v0.2.0-alpha.1 was later retired unused (ADR-0048) — the first public tag, v0.3.0-alpha.1, ships durability and JSON documents included.

M2 — Durability DONE · GO VERDICT

The log spine complete: segments, batch frames, CRC, group commit, manifest; everysec/always namespaces with watermark-gated acks; fuzzy fork-free checkpoints with truncation; parallel recovery; the fault-point harness and crash matrix; deterministic disk-fault simulation (torn writes, fsync lies, power cuts); INF.CKPT/BGSAVE. The binding campaign ran on the designated reference box: the correctness gates passed (see the durability evidence); several device-bound performance rows were honestly dispositioned as Evidence-pending on Gen4-class hardware rather than narrowed. Verdict: GO — the release act itself later moved to M3 (ADR-0048).

M2.5 — Hardening & first alpha DONE · RELEASE ACT → M3

No new command surface. The milestone that turned M2’s GO verdict into a hardened, evidence-clean core before the feature train resumed — performance-first per ADR-0025:

  • Paid the debt: the boot-wedge stop-item root-caused and fixed; measured performance levers on group formation, recovery read-ahead, and the cross-cell remote-penalty campaign — each A/B’d on the designated box and dispositioned by ADR (losing levers recorded and not merged); the anchored cross-cell gate ratified by ADR-0035.
  • Shipped the instrument: the first binding comparative campaign with the zero-dependency inf-compare harness, this website and docs v1, and full evidence closure — zero undispositioned claim-ledger rows (the S19 walk, 2026-07-10).
  • Hardened: TigerBeetle-grade assertion and soundness audits, deeper simulation fleets, fuzz-hour accumulation, and the documents-first seam-readiness review for M3 (ADR-0032). Per ADR-0048, the tag + announcement act folded into M3 — v0.2.0-alpha.1 was retired unused rather than shipping an alpha its successor would immediately supersede.

Now

M3 — JSON documents IN PROGRESS → v0.3.0-alpha.1 · FIRST PUBLIC TAG

JSON objects as first-class values, not a module: a compact binary document tree (tape-structured for parse-free traversal), the RedisJSON-compatible JSON.* surface with a compiled JSONPath subset, in-place path mutation, delta log records with periodic full-document records to bound replay, and a compat suite with RedisJSON as the oracle. This opens the NoSQL story: entities as documents under designed keys — and it carries the project’s first public tag: the release act (pre-tag binding campaign, ledger re-validation, signed announcement, release pipeline) ships here per ADR-0048.

Next

M4 — Tiered storage v0.4.0-alpha

Beyond-RAM datasets via the hybrid-log design (Microsoft FASTER lineage): one logical address space per cell spanning disk, read-only RAM, and mutable RAM regions; async cold reads through the executor; compaction in budgeted slices; blob extents. Cache-mode namespaces are the degenerate case and never execute this code.

M4.5 — Indexes & query v0.4.5-alpha · ADR-0024

Typed secondary indexes over document paths (INF.IDX) on the per-cell ordered key-range projection, plus a planner-free PartiQL subset over RESP (INF.QL + EXPLAIN): one access path per statement, grammar-driven compilation, residual filters on a predicate VM, no cost model, no joins — anything outside the subset is rejected with a documented error. The DynamoDB discipline: access paths are keys and declared indexes, never a planner’s guess.

M5 — Data types v0.5.0-alpha

Hashes, lists, sets, sorted sets, bitmaps, bitfield, HyperLogLog; small→large encoding morphs with measured thresholds; the SCAN family; keyspace notifications; the compat matrix grows to roughly the full conventional Redis surface.

M6 — Transactions & scripting v0.6.0-alpha

MULTI/EXEC/WATCH (single-cell inline; cross-cell via deterministic two-phase intent locking, the Dragonfly-proven shape), Lua with declared keys, a FUNCTION subset.

M7 — Streams & queues v0.7.0-beta.1 · FIRST BETA

Topics and partitions directly on the log spine; the full Redis Streams surface; Kafka-style offset consumption, producer idempotence, DLQs, delayed delivery; retention; client tracking and client-side caching; AUTH + TLS (beta means people deploy it); RDB import for migration.

M8 — Vectors v0.8.0-beta

Redis-8-compatible vector sets plus INF.VEC collections: per-cell HNSW graphs, SQ8 quantization with rescoring, scatter-gather k-NN over the fabric, filter predicates. Vectors are ordinary durable records — replicated and tiered like everything else.

M9 — Replication & HA v0.9.0-beta

Per-cell log shipping to replicas, wait-replica ack gating, read-from-replica with session watermarks, a Raft control plane for election and failover (data never flows through Raft), object-storage backups with point-in-time recovery, live migration by posing as a Redis replica — verified by Jepsen-style harnesses and simulated cluster scenarios before any HA claim.

M10 — Compute & enterprise v0.10.0-rc.1

The WASM reducer host: sandboxed modules running inside the process on the core that owns their data — fuel-metered, memory-capped, capability-scoped, transactional. Plus the embedded Rust crate, shared-memory IPC transport, full ACLs, and the documented seam inventory the post-1.0 extension SDK stabilizes against.

M11 — GA hardening 1.0.0

No features: long mixed-profile soaks, fuzz-corpus expansion, a full performance re-baseline with claim-ledger re-validation, the compatibility matrix frozen and published, the extension-seam freeze, and a third-party security audit. 1.0.0 means: single-node and replicated InfinityDB serving cache, durable KV, JSON documents (memory-exceeding), streams/queues, and vector search over RESP, with WASM reducers and embedded/IPC modes — every public number evidence-backed.

Post-1.0 horizon COMMITTED DIRECTION, UNCOMMITTED DATES

Cluster mode (slot migration — the 16,384-slot space was designed for it from day one); the native extension SDK; live queries/subscriptions over RESP3 push; protocol gateways in priority order — DynamoDB-compatible HTTP, native HTTP/JSON + WebSocket, PartiQL over those gateways, a Kafka wire-protocol gateway. A MongoDB wire listener is evaluated, not committed. Scope fences hold until then: no SQL planner, no multi-region active-active, no Redis modules ABI.
