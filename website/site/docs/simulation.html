      Concepts/Deterministic simulation

      Deterministic simulation

      Time, randomness, network and disk are injected, so the whole node, every cell included, runs on one thread inside a simulator. The same seed gives the same execution, byte for byte. Every failure is a seed you can replay.

      Available · alphaLaw L7

      The real cell code, driven by a seeded scheduler over a simulated network, disk and clock, with oracles watching every step.

      The whole node, one thread

      inf-sim is not a model of InfinityDB. It runs the real server and loop code (every cell, the fabric, the wire protocol, the store, the log and recovery) through a third implementation of the backend driver, beside io_uring and kqueue. A seeded scheduler picks which cell or client runs next and advances a virtual clock in seeded steps.

      This works because the cell code never reaches for the outside world on its own. The loop takes a Clock, randomness comes from seeded SplitMix64 streams, sockets and the ring sit behind the BackendDriver trait, and every log and tier file effect goes through a SegmentFs trait. Where iteration order could reach output, cell code uses BTreeMap or a fixed hasher, never a per-process random seed. Because the clock is virtual, a scenario can run a long expiry schedule without waiting for wall time to pass.

      Simulated faults

      • Network. In-memory sockets split received bytes at seeded points, which drives every resume path of the RESP parser.
      • Disk. For every file the simulated disk keeps what the OS would show and what would survive a power cut. Unsynced data is lost on a cut. Pending writes are cut into sectors that each survive a coin flip and land in a seeded order, so writes tear and reorder. Directory operations survive only in a seeded prefix.
      • Power cuts. Scenarios cut power at seeded points, including during recovery itself, then boot again and audit what survived.
      • Fault points. Named fault points in the storage code are compiled only into test and simulator builds, and a check keeps them out of shipping builds.
      • Identity. The key-hash secret is derived from the seed, so hash placement replays too.

      An armed fault must prove it fired. A scenario whose fault never engaged reports VACUOUS, never a green result.

      Oracles and canaries

      Oracles watch every run:

      • every key's replies, replayed against a model store in apply order on the same thread;
      • an independent shadow model written from Redis's documented semantics, which shares no store code with the server;
      • pub/sub delivery: in order, no loss, no duplicates;
      • memory accounting and key contents at quiescence, and no leaked connections;
      • no acknowledged always write lost across crashes;
      • after seeded power cuts, every live key of a tiered namespace serving its exact bytes and every deleted key gone;
      • document replay equivalence, index backfill and saved-index equivalence;
      • a stall detector that fails a run making no progress, the tripwire for a lost wakeup.

      An oracle that cannot go red proves nothing, so each one has a canary: a planted bug, compiled in only for the canary run, that must turn it red while the plain build stays green. A lying fsync that reports success for data it never made durable must be caught within 1,000 seeds of the durability scenario. A GET that appends one byte to its reply must be caught by the shadow model, because the shared-store replay runs the same code and cannot see it. Other plants include a lost wakeup, an accept error, a tier read that fails with EIO and a log segment's leftover frames from a previous life.

      Run it

      The simulator refuses to build without the dst feature. From the repository root:

      shell · scroll →
      $ just sim-smoke
$ cargo run --release -p inf-sim --features dst --bin inf-sim -- \
    --scenario m2-durable --seed 0xC0FFEE --verify-determinism
$ just sim-canaries
$ just durable-sweep 10000 0xD5EE0000
      CommandWhat it does
      just sim-smokeEvery scenario the binary accepts, determinism-verified. PR CI runs the same script.
      --verify-determinismRuns a seed twice and compares the traces and a hash of the final state, disk included.
      just sim-canariesBuilds each planted bug and requires its scenario to go red.
      just durable-sweep [seeds] [base]Thousands of seeds of the durability scenario, sharded; doc-sweep, budget-sweep, transition-sweep, reorder-sweep and recycle-sweep follow the same shape.
      --plant NAMEInjects a known bug by hand: lost-wakeup, fsync-lies, accept-error, tier-read-eio or stop-kill.
      --list-scenariosPrints every scenario name, from m0-smoke to m4-tiered and the index scenarios.

      When you report a simulator failure, the scenario and seed are the whole reproduction.

      Seeds and the nightly fleet

      bins/inf-sim/seeds/corpus.txt records every seed that ever caught a bug, and the corpus replays green on every merge to main. When a fresh seed fails, the fix lands with that seed appended, so the bug cannot quietly return. Every night a fleet replays the corpus at full size, runs fresh seeds derived from the run id, runs the sweeps and the canaries, and runs long expiry campaigns in virtual time. A failure files an issue carrying the scenario, the seed and the commit.

      Keeping the simulator's authority

      One ambient call to the wall clock would make a run unrepeatable, so the rule is mechanical. scripts/check-cell-denylist.sh rejects tokio, standard mutexes, read-write locks, condition variables and channels, thread spawn, sleep and park, Instant::now, SystemTime::now and ambient randomness in every cell crate. Clippy's disallowed-methods backs the clock ban with type resolution, so a renamed import does not slip through. A sanctioned site, such as the injected clock's own origin, carries a denylist-allow: marker with a reason, and the script lists every such site when it passes. Like every gate, it is self-tested inside just check: a planted violation must turn it red.

      L7
      Determinism is a feature.

      Every effect a cell has on the world goes through an injected seam. That is what lets the simulator own time, entropy, the network and the disk, and what turns a once-a-week concurrency failure into one seed and an exact trace.
