Quickstart

InfinityDB speaks the Redis wire protocol, so the only client you need to try it is redis-cli (or any Redis SDK). It is an early alpha: single-node, no authentication or TLS yet (both arrive at M7), not production-ready.

Honest packaging note: the first public tagged release, v0.2.0-alpha.1, is in preparation (milestone M2.5). Until it lands there are no published binaries and no published container images — both paths below build from the repository. When the release pipeline runs on the first tag, prebuilt static Linux binaries and an image will be attached to the release.

Requirements

  • Linux with io_uring — kernel 5.15+ (6.1+ recommended). InfinityDB’s I/O plane is built on io_uring from the ground up; this is not optional on the serving path.
  • Rust 1.95+ for the source build.
  • macOS builds for development only via kqueue — it is not a performance or deployment target.

Path A — build from source

# from the repository root, inside infinitydb/
just check                            # fmt + dep-DAG law + cell deny-list + clippy + tests
cargo build --release -p infinityd
./target/release/infinityd --port 6379

Then, from another terminal:

redis-cli -p 6379 ping                # PONG
redis-cli -p 6379 set hello world     # OK
redis-cli -p 6379 get hello           # "world"

Path B — build the Docker image from the repo

The repository carries a Dockerfile (static musl build into a scratch-based image). Build and run it locally:

# from the repository root, inside infinitydb/
docker build -t infinitydb:dev .

docker run --rm -p 6379:6379 \
  --security-opt seccomp=deploy/seccomp/infinitydb-seccomp.json \
  infinitydb:dev
The --security-opt seccomp=… flag is required. InfinityDB uses Linux io_uring, and Docker’s default seccomp profile blocks the io_uring syscalls (io_uring_setup and friends). The bundled profile at deploy/seccomp/infinitydb-seccomp.json re-enables io_uring while still denying the dangerous container-escape syscalls. Alternatives (including a strict allow-list posture and why seccomp=unconfined is development-only) are on the deployment page. If the container exits complaining about io_uring setup, seccomp is the cause.

Running with a mounted data directory, systemd units, the data-dir layout, and every server flag are on the deployment page.

First durable namespace

Durability in InfinityDB is a property of the namespace, not the server. A fresh node serves memory-mode namespaces (pure cache semantics). One command creates a durable one:

redis-cli -p 6379
inf> INF.NS CREATE orders MODE durable FSYNC always
inf> SET orders:invoice:1009 "paid"     # the reply arrives only after group-commit fsync
inf> INF.CKPT WAIT                       # take a fuzzy checkpoint; returns when the MANIFEST is durable

What always, everysec, and memory mean precisely — ack points, loss windows, crash behavior, recovery — is specified on the namespaces & durability page. Read it before trusting the durable modes with anything you care about; it is short and unusually honest.

Client libraries

Any Redis client works — InfinityDB negotiates RESP2 and RESP3 (HELLO 3) like Redis does. These four libraries are exercised end-to-end in the repository’s client-smoke suite (tests/client-smoke/ — connection negotiation, strings, expiry, INFO, SCAN iteration, pub/sub); the snippets below use the same API calls the smoke scripts run.

redis-py (Python)

# pip install redis
import redis

r = redis.Redis(host="127.0.0.1", port=6379, decode_responses=True)
assert r.ping() is True
r.set("greeting", "hello")
print(r.get("greeting"))        # hello
r.expire("greeting", 100)
print(r.ttl("greeting"))        # 100 (or just under)

node-redis (Node.js)

// npm install redis
import { createClient } from "redis";

const client = createClient({ socket: { host: "127.0.0.1", port: 6379 } });
await client.connect();
console.log(await client.ping());          // PONG
await client.set("greeting", "hello");
console.log(await client.get("greeting")); // hello
await client.quit();

go-redis (Go)

// go get github.com/redis/go-redis/v9
package main

import (
	"context"
	"fmt"

	"github.com/redis/go-redis/v9"
)

func main() {
	ctx := context.Background()
	r := redis.NewClient(&redis.Options{Addr: "127.0.0.1:6379"})
	fmt.Println(r.Ping(ctx).Val())            // PONG
	r.Set(ctx, "greeting", "hello", 0)
	fmt.Println(r.Get(ctx, "greeting").Val()) // hello
}

Lettuce (Java)

// io.lettuce:lettuce-core
import io.lettuce.core.RedisClient;
import io.lettuce.core.api.StatefulRedisConnection;
import io.lettuce.core.api.sync.RedisCommands;

RedisClient client = RedisClient.create("redis://127.0.0.1:6379");
try (StatefulRedisConnection<String, String> conn = client.connect()) {
    RedisCommands<String, String> r = conn.sync();
    System.out.println(r.ping());          // PONG
    r.set("greeting", "hello");
    System.out.println(r.get("greeting")); // hello
} finally {
    client.shutdown();
}
