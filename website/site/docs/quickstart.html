      Get started/Quickstart

      Quickstart

      Run InfinityDB locally, connect with the Redis tools you already have, then give one namespace real durability.

      Alpha software

      InfinityDB is single-node and not production-ready. It has no authentication or TLS yet and listens on every interface, so keep it bound to localhost, and keep copies of anything you care about.

      1Start the server

      No release has been published yet, so build the image from the repository. It listens on 6379, the Redis default, so existing tools connect unchanged.

      shell · scroll →
      $ git clone https://github.com/kevincaicedo/infinitydb && cd infinitydb
$ docker build -t infinitydb:dev .
$ docker run --rm -p 127.0.0.1:6379:6379 \
    --security-opt seccomp=deploy/seccomp/infinitydb-seccomp.json \
    -v infinitydb-data:/data \
    infinitydb:dev --data-dir /data

      The seccomp profile is required: InfinityDB is built on io_uring, and Docker's default profile blocks it. The volume and --data-dir give the node somewhere durable to write. The first boot of a new data directory measures the device before it accepts connections; the node is ready when it prints control: recovery complete.

      On Linux 5.15 or newer with Rust installed, you can run the binary directly instead:

      shell · scroll →
      $ cargo build --release -p infinityd
$ ./target/release/infinityd --port 6379 --data-dir ~/infinity-data

      2Connect with redis-cli

      Any Redis client works. Start with the basics.

      redis-cli · scroll →
      $ redis-cli -p 6379
127.0.0.1:6379> PING
PONG
127.0.0.1:6379> SET greeting "hello" EX 60
OK

      3Make a namespace durable

      Durability belongs to the namespace, not the server. Pick the guarantee each workload needs.

      ModeAcknowledgedLost if the machine dies
      memoryon apply, no logeverything: cache semantics
      everysecon apply, fsync every secondup to one second
      alwaysafter the group fsyncnothing, on a single node
      redis-cli · scroll →
      127.0.0.1:6379> INF.NS CREATE ledger MODE durable FSYNC always
OK
127.0.0.1:6379> INF.NS USE ledger
OK

      INF.NS USE binds this connection to the namespace, the way SELECT binds a database. The numbered databases behind SELECT 0..15 are always memory-only, so a connection that never binds writes to a cache. The full contract is on Namespaces & durability.

      4Store a JSON document

      Documents are first-class values, mutated by path. Hash tags like {sku9} keep a document and its related keys on the same core.

      redis-cli · scroll →
      127.0.0.1:6379> JSON.SET catalog:{sku9} $ '{"name":"Lens","price":4999}'
OK
127.0.0.1:6379> JSON.NUMINCRBY catalog:{sku9} $.price -500
"[4499]"
127.0.0.1:6379> JSON.GET catalog:{sku9} $.name
"[\"Lens\"]"

      Stop the server with Ctrl-C and start it again with the same command. The stop is graceful, the namespace is durable, and the document is still there.
