      Engineering/Design laws

      Design laws

      Thirteen laws shape every design and every change. Each one is enforced by the strongest mechanism available, and a law changes only by a recorded amendment, accepted before any code that depends on it.

      NormativeL1–L13

      A change that weakens a law starts as an issue, not a pull request; an accepted change is recorded as a numbered decision before the code. The full rules live in CONTRIBUTING.md and InfinityStyle.

      L1 · One core, one shard, one owner.

      Every key has one owning cell, and cells share no mutable data-plane state: no locks and no shared atomics on the per-key path, only the fabric. Expiry, eviction and accounting become local, single-threaded problems. Command futures are !Send and the executor's wakers use no atomics. Guards: check-cell-denylist.sh, backed by clippy's disallowed-types, rejects locks, channels and tokio in cell crates; a CI check scans the waker path for atomic instructions. The stated cost: one hot key lives on one core.

      L2 · The log is the database.

      Every durable fact is a log append first. The index, documents, tier files, checkpoints and secondary indexes are projections, rebuildable from the log or from a checkpoint that is itself a log prefix. Checkpoint load and replay share one idempotent upsert, so there is one recovery path. Guards: the crash matrix kills the process at named fault points and compares recovery with a reference replay; the simulator's replay oracles do the same under seeded power cuts.

      L3 · Batch every boundary.

      Syscalls, fabric hops, fsyncs and cache misses are paid once per batch: one io_uring_enter per loop iteration, at most one log frame and one barrier per iteration, many fabric messages per ring slot, index lines prefetched for a whole batch. Guard: the batching ratios are always-on tripwires in INFO tripwires, and a benchmark whose tripwires show the batching did not happen is not a valid measurement.

      L4 · Mechanical sympathy is measured.

      SIMD, prefetching and layout tricks are hypotheses until measured. An optimization ships with an A/B against a named baseline or stays behind a flag, and a losing A/B is recorded and not merged. Correctness fixes merge on their tests. This law is enforced in review, through the pull-request checklist.

      L5 · Memory is the product.

      For a cache, memory per key is the cost. Records carry an 8-byte header, the index slot is 8 bytes and holds no key, and eviction bits live in spare header bits. Every byte is attributed at its allocation site to a named, counted domain. Guards: the exit-gate harness fails a run whose domains drift from process RSS beyond its tolerance, and the simulator reconciles accounting at quiescence.

      L6 · Every command is a resumable state machine.

      A command that may wait, for another cell, a durable acknowledgment, log space or a cold read, suspends on a typed gate. A local command on a numbered database runs inline with no future and no task, so the fast path pays nothing. Nothing borrowed before a suspension is trusted after it. Guard: handles are shaped so that holding one across an await fails to compile where the types allow; review checks the rest on every change.

      L7 · Determinism is a feature.

      Time, randomness, network and disk are injected through a Clock, seeded SplitMix64 streams, the BackendDriver trait and the SegmentFs trait, so the whole node runs inside the simulator and every failure is a seed. Guards: the cell denylist, and check-clock-ban.sh, which proves that clippy rejects every spelling of an ambient clock.

      L8 · Compatibility is staged and honest.

      Redis compatibility is declared per command. The matrix records the differences the corpus finds and the ones a row's note declares; it does not show that no other difference exists. The matrix is generated from the command table and a corpus diffed byte for byte against Redis 8.0.5 and a pinned RedisJSON, in-process and against a multi-cell server. Guard: CI fails when compat-matrix.md is stale or a corpus reply differs from its oracle with no recorded deviation for the case.

      L9 · Safety is layered.

      unsafe lives only in a few audited leaf crates and named modules; every other crate root forbids it. Each block carries a // SAFETY: argument and a SAFETY.md entry. Every decoder, from client requests to every on-disk format, is iterative, bounded and total, and lands with its fuzz target. Guards: check-unsafe-roots.sh, the denied undocumented_unsafe_blocks lint, the inventory check, Miri, Loom and nightly fuzzing.

      L10 · Claims follow evidence.

      No performance number is published without a reproducible measurement on known hardware with a control run, and a target is never shown as a result. Evidence that cannot go red is not evidence, so every oracle has a canary: a planted bug that must turn it red. Guards: check-scripts-selftest.sh plants a violation in front of every gate inside just check, and just sim-canaries requires each planted bug to turn its scenario red.

      L11 · Extensibility is a seam, not a fork.

      Engines attach through versioned seams: the command table, record type tags, log record types and index projections. They never reach around them. The document engine is the stated exception today, linked by the store behind its own feature. Guards: check-dep-dag.sh fails on any crate edge not listed in dep-dag.toml, and CI checks that the slim server library holds no document or query code.

      L12 · Design is proven before code.

      A change that adds state, a limit, a queue, a format, a decoder or a crate edge starts as a written design, reviewed by someone who did not write it, before any code. It draws the state machine as a table, states the cost at scale and each limit's crossing behaviour, names the oracle for hostile inputs, and names the observation that would reject it. Guard: review; frozen interfaces and formats change only by an accepted decision first.

      L13 · One decision, one place.

      Each rule has one home, enforced by the strongest mechanism available: a type, then a lint, then a generated table, then a self-tested script, and only then review. The command table is the model: routing, flags, COMMAND and the compatibility matrix all read one static table, and a collision in its compile-time perfect hash fails the build. There is no second dispatcher and no hand-kept list. Guards: the lint ratchet, whose counts only go down, the generated tables and the gate self-test.
