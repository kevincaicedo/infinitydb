      Operate/Configuration

      Configuration

      How to run a node beyond a quick trial: Docker with the io_uring seccomp profile, a systemd unit, what the data directory holds, which ports exist, every server flag, and the upgrade rules for the on-disk format.

      Available · alpha
      Alpha exposure

      There is no authentication and no TLS yet, and the server listens on every interface. AUTH, requirepass and bind-address control arrive later in M4, before the first public tag; TLS and multi-user ACLs with M7. Until then, run InfinityDB only on localhost or a trusted private network.

      Docker

      There are no published images until the first public tag. Build the image from the repository: the Dockerfile produces a static musl binary in a scratch image, with no shell and no libc.

      shell · scroll →
      $ docker build -t infinitydb:dev .
$ docker run --rm -p 127.0.0.1:6379:6379 \
    --security-opt seccomp=deploy/seccomp/infinitydb-seccomp.json \
    -v infinitydb-data:/data \
    infinitydb:dev --data-dir /data

      The volume and --data-dir /data give the node durable storage; omit both to run memory-only, where nothing survives a restart. -p 127.0.0.1:6379:6379 publishes the port on the host's loopback interface only.

      The seccomp profile is required

      Docker's default seccomp profile blocks the io_uring system calls (io_uring_setup, io_uring_enter, io_uring_register). Under it the node cannot create its reactor and exits at once with:

      stderr · scroll →
      infinityd: cell failed: Operation not permitted (os error 1)
      • The bundled profile, recommended: deploy/seccomp/infinitydb-seccomp.json allows io_uring and still denies the container-escape calls such as mount, pivot_root, module loading, kexec_load, bpf, ptrace and perf_event_open.
      • A strict allow-list: take Docker's default profile and add the three io_uring calls to an allow entry.
      • seccomp=unconfined: development on a trusted machine only.

      A binary run directly on the host is not subject to Docker's profile. Kubernetes and CI runners differ; if a containerised node exits with the error above, seccomp is the cause.

      systemd

      infinityd runs in the foreground, logs to stderr, and stops gracefully on SIGTERM or SIGINT, so Type=simple is correct.

      infinitydb.service · scroll →
      [Unit]
Description=InfinityDB node
After=network-online.target local-fs.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/infinityd --port 6379 --data-dir /var/lib/infinitydb
User=infinitydb
Group=infinitydb
StateDirectory=infinitydb
# A refusal to boot or a failed fsync is evidence for an operator.
# Do not turn it into a silent restart loop.
Restart=no
LimitNOFILE=1048576
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/infinitydb

[Install]
WantedBy=multi-user.target
      • Restart=no is a recommendation. The deliberate exits, a recovery refusal (exit 1), a durable fsync failure (exit 3) and a cell panic (exit 101), all mean the same thing: restarting will not help, and a loop hides the evidence. Observability explains each one.
      • A stop is graceful; a crash is still safe. On SIGTERM every cell stops admitting and drains, a durable cell publishes a stop checkpoint and its final sync, and the node exits 0: the next boot replays nothing. --shutdown-timeout-ms bounds the drain; when it expires the node exits 1 and names the phase. A second signal ends it at once.

      The data directory

      With --data-dir set, the node owns this tree. Metadata files are checksummed and replaced atomically; log segments are checksummed frames, append-only.

      <data-dir>/
├─ LOCK                  # owner lock: a second process on the directory is refused
├─ topology.toml         # the --cells count, stamped at first boot
├─ io-properties.toml    # the device probe's result, bound to this device
├─ key-hash.toml         # the key-hash secret: back it up with the directory
├─ META                  # the namespace catalog
├─ shard-0/              # one directory per cell, recovered independently
│  ├─ MANIFEST           # the recovery unit: checkpoint, begin position, live segments
│  ├─ log/seg-000000.ilog
│  └─ ckpt/ckpt-000001.ick
└─ shard-1/ …
      • Segments plus the checkpoint they truncate into are the complete durable state. Back up the whole directory; a consistent snapshot of it is a valid recovery unit.
      • Do not edit, rename or delete files inside the tree. Recovery treats missing or altered named state as corruption and refuses to start, on purpose.

      Ports

      Exactly one TCP port, 6379 by default. RESP2 and RESP3 (HELLO 3) are negotiated on it. There is no cluster bus, no gossip and no metrics port: observability rides INFO on the same connection.

      Server flags

      Flags only, no config file. The ones an operator sets:

      FlagDefaultMeaning
      --port6379TCP port to listen on.
      --cells4Shard cells: one thread and one shard-k/ directory each. Fixed for the life of a data directory.
      --data-dirunsetDurable-plane root. Without it the node is memory-only and the durable machinery is absent from the hot path.
      --conn-default-nsunsetThe namespace a new connection starts in, instead of database 0.
      --ckpt-interval-bytes268435456Bytes appended per cell before a checkpoint. 0 means manual only.
      --segment-bytes268435456Log segment size.
      --device-probeautoAt the first boot of a data directory, measure the device and record the write model in io-properties.toml. off skips it and uses conservative write settings.
      --shutdown-timeout-ms10000Bound on the graceful stop's drain.
      --buffers, --buf-size4096, 4096The io_uring provided-buffer pool: count and bytes per buffer.
      --pin-start, --pin-strideunset, 2Pin cell i to core pin-start + i × pin-stride. Unset means no pinning.
      --versionPrint version, git SHA and build target, then exit.

      The remaining flags in infinityd --help tune the write path, the idle loop and the fabric, or select an experiment arm. Their defaults are the ones to run with. Runtime settings use the Redis CONFIG surface (maxmemory, maxmemory-policy); per-namespace settings are given to INF.NS (see Memory & eviction).

      Upgrades

      • Reading is forever. Every later build reads every earlier log frame format.
      • No downgrade after the first write. Once a newer binary has appended to a log, rolling the binary back means restoring the data directory from a backup taken before the upgrade.
      • Format changes are recorded design decisions. Each lands with fuzzing of both formats, a crash-matrix run and a fresh simulation sweep.
