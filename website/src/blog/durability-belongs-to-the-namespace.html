M2 builds the log spine and makes durability a property of the namespace, not of the server. A namespace picks its promise when it is created: memory, everysec or always. Each cell has one log, and it keeps all three promises, the memory one by never being touched. The gate campaign that measured them ran on the reference box, and its central finding was not a number. It was a real defect in group commit, one that every rehearsal on tmpfs had certified as healthy.

1A promise per namespace.

The classes differ in one thing: when the reply goes out, relative to the disk.

  • memory: acknowledged on apply, never logged, gone on restart. Cache semantics, at no cost to the log.
  • everysec: acknowledged on apply. Group commit runs every loop iteration, and a one-second timer makes sure a barrier runs. As with Redis's appendfsync everysec, a power loss can lose up to about one second of acknowledged writes.
  • always: the write applies at once, but its reply waits until a barrier covering its log record has completed. Nothing is acknowledged before it is durable.
127.0.0.1:6379> INF.NS CREATE orders MODE durable FSYNC always
OK
127.0.0.1:6379> INF.NS USE orders
OK
127.0.0.1:6379> SET order:1 shipped
OK

The numbered databases, SELECT 0 to 15, are always memory-only. A durable namespace never evicts, because evicting a key without logging a delete would bring the key back on replay.

2One log per cell, shared by every class.

The log is per cell: checksummed frames in append-only segments, and a MANIFEST that names the checkpoint, the segment set and the truncation point in one atomic swap. A record's address is a segment and an offset in one cell's log. There is no global sequence number, so every cell recovers on its own, in parallel.

Each iteration seals at most one frame, written with one write, and one barrier covers every durable write due. One end-to-end test interleaves memory, everysec and always namespaces on a single cell of a real io_uring node: each class keeps its own acknowledgment semantics, they share one frame and one fsync per iteration, and the memory namespace appends zero log records, asserted through a counter rather than inferred.

Law derived · L2

The log is the database. One mechanism carries every durable fact, so there is one thing to make correct, and the classes that skip it really do skip it.

3Nothing is served before it is durable.

An always reply is held on a gate keyed to the durable watermark, so it is structurally unreachable before the sync that covers it. The watermark advances only over the longest prefix of the log in which every barrier has completed; a later completion alone proves nothing about the bytes before it.

Failure is loud. A failed fsync is fail-stop: the process exits, no write in the failed batch is acknowledged, and a check in just check keeps that error type out of any match arm that would carry on. Retrying an fsync against pages the kernel may already have dropped is how a database loses data quietly. Recovery truncates a torn final frame, which is expected after a power cut, but a corrupt frame with valid data after it means the disk lied, and the node stops with a named error.

The simulator's durability oracle checks every acknowledgment against what survives a seeded power cut, and it must catch a planted driver that reports a sync it never performed, or its silence means nothing.

4The defect the gate caught.

The first binding run on the reference box measured the always row well under its gate, with far fewer acknowledgments per fsync than the load offered. Every iteration that carried always traffic linked its own fdatasync. On a device with real fsync latency, dozens of tiny syncs queued behind each other, each covering about one iteration's records. It was the batch-of-one disease that sank Vortex's I/O plane, this time at the device.

Nothing earlier had seen it. On tmpfs an fsync costs almost nothing, so each sync finished before the next iteration and grouping looked fine. Simulated fsyncs complete deterministically, so the simulator missed it too: after the fix, the 10,000-seed sweep produced byte-identical results. Only the device made it visible.

The fix makes the design literal: one durability fsync in flight. Barriers that come due while a sync is outstanding wait behind it and issue when it completes, covering everything queued since. Segment-seal syncs stay ungated, and the everysec window still holds. A unit test pins the discipline: twelve frames, two fsyncs.

Law derived · L3

Batch every boundary. An fsync is paid per batch, never per write, and a rehearsal on a device where the barrier is free cannot see a batching defect. The device that charges for the barrier is part of the test.

5Disclosed, not narrowed.

The always row still did not reach its gate on this box. The reference box's drive is a consumer PCIe Gen3 DRAM-less NVMe, a disclosed deviation from the Gen4 class the device-bound gates were written for. So always throughput, the everysec penalty and the absolute checkpoint tail are Evidence-pending with the device named as the limiter. Per-cell replay was rejected on this box, with its remedy named: overlap read-ahead with apply. No gate value was narrowed.

The rest of the campaign is the subject of the reference-box re-run before the first release; until then its rows stay pending on this site, whatever a development run says.

What the namespace owns.

A namespace now owns its promise, and a cell keeps all of them with one log. The campaign showed why promises are measured on hardware that can say no: the gate that failed found a real defect, and the fix landed with a test that pins it. The durability and log pages cover the classes, frames and recovery.
