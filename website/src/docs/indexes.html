Not usable yet

The command table has no index DDL, no query command and no EXPLAIN today, and the server does not link the query crate, so a client has no way to declare an index or run a query. This page describes work in progress so you can follow it; nothing here is available in a build you run.

What is built and tested

These parts exist in the code, with their own tests, oracles and fuzz targets:

PartWhat it does
Ordered indexA per-cell B+-tree of (typed key, document reference) pairs in memcmp order. Numeric keys are 8-byte flat arrays; variable-length keys go up to 1 KiB; leaf search uses SIMD. Cursors never pin a node: they remember their last pair and seek again when the tree has changed.
Typed keysUTF-8 strings, 64-bit integers, doubles and booleans encode so that byte order equals value order. One coercion table decides what a document value becomes as a key, for maintenance and queries alike.
MaintenanceA write to an indexed namespace evaluates the index paths on the old document, applies the mutation, evaluates them on the new one and applies the difference to the trees, in the same step on the same thread. No observer sees a document and its index disagree.
BackfillA new index fills by a budgeted background walk. It moves from declared, to backfilling, to ready only when every cell reports the same generation.
PersistenceConverged trees are saved inside checkpoints. At boot an index is loaded or rebuilt, and a damaged saved index can never stop a boot.
Predicate VMAn iterative bytecode interpreter for filters, with a fuel limit, that allocates nothing.
Query compilerTurns a PartiQL statement into exactly one access step, an optional filter and a page bound, or rejects it with a fixed message.

Index bytes are counted in the memory domains (used_memory_idx_tree, used_memory_idx_slack) and in namespace budgets.

The PartiQL subset

The full contract, with every rejection message, is docs/partiql-subset.md. In summary:

SELECT ( * | COUNT(*) )
FROM   ns | ns.index | ns.SCAN
[WHERE condition]
[LIMIT integer]
  • FROM ns serves a primary-key get ($key = 'k') or the one ready index whose path the conditions name. FROM ns.index names the index. FROM ns.SCAN is the explicit consent to read the whole namespace; an unindexed query is never quietly turned into a scan.
  • Conditions use =, !=, <>, <, <=, >, >=, BETWEEN, IN with 1 to 100 members, begins_with(path, 'prefix') and exists(path), combined with AND, OR, NOT and parentheses, nested at most 32 deep.
  • Paths are written without the $. root: price, items[0].id, tags[*]. Recursive descent, slices and unions are rejected.
  • Statements are UTF-8, at most 8,192 bytes. ORDER BY, GROUP BY, HAVING, JOIN, OFFSET, LIKE, IS NULL and INSERT, UPDATE or DELETE are rejected, each with its own message.

Planner-free by construction

There is no cost model and no plan search. The compiled form has room for exactly one access step: a primary-key get, one index range, or a consented scan. When the conditions match two ready indexes, the compiler refuses and asks you to name one, instead of choosing. When they match none, it refuses and points you to declaring an index or to FROM ns.SCAN. A reversed BETWEEN compiles to an empty range: zero rows, not an error.

Results page through opaque cursors. A page is bounded by entries scanned, not entries matched, so a selective filter cannot make one page unbounded. LIMIT caps the total matches across pages, and COUNT(*) pages too: each page returns a partial count with the number of entries examined.

Evaluation rules

  • Existential matching. A comparison on a path with several values is true if any value satisfies it. So on multi-valued paths != is not NOT(=): [1, 2] != 1 is true, while NOT([1, 2] = 1) is false.
  • Two-valued verdicts. There is no SQL UNKNOWN. A missing path or a type mismatch is false and sets a flag; NOT flips the verdict only.
  • One numeric truth table. 3 = 3.0 is true, and comparisons across integers and doubles are exact, never lossy.
  • Fuel. Every statement runs under a fuel budget. Running out is a typed error, never a truncated or silently false result.

What comes next

Still to be reachable from the wire: index DDL, the query command, EXPLAIN, the cursor wire format, the fabric operation that carries a query to other cells, and JSONPath filter expressions (?(@…)) in JSON.* paths. The command surface lands after the work that bounds and reserves capacity across the engine. Indexes over documents in tiered namespaces, and queries that stay on one cell for a tenant's co-located keys, follow with documents beyond RAM, the last phase of M4.

The roadmap tracks the milestone, and the compatibility matrix will list these commands once a client can send them.
