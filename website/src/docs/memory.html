The node budget

maxmemory is a node-wide budget, and each cell enforces its share, maxmemory / cells. Cells own equal slot ranges, so this needs no shared state. The default is 0, no limit, with the noeviction policy. Both keys change at runtime:

127.0.0.1:6379> CONFIG SET maxmemory 256mb
OK
127.0.0.1:6379> CONFIG SET maxmemory-policy allkeys-lfu
OK
127.0.0.1:6379> CONFIG GET maxmemory
1) "maxmemory"
2) "268435456"

Sizes use Redis units: kb, mb and gb are powers of 1024, k, m and g powers of 1000. The write path pays one branch on a cached over-limit flag. Over the limit, a write may evict up to 512 keys inline; if that is not enough, it gets Redis's exact error, OOM command not allowed when used memory > 'maxmemory'. Background slices then evict down to a lower target. Nothing panics under memory pressure: an allocation that cannot be met returns "no memory" and the command gets the error.

Eviction policies

PolicyCandidatesOrder
noevictionnonewrites that need memory are refused
allkeys-lru / volatile-lruall keys / keys with a TTLrecency, by CLOCK
allkeys-lfu / volatile-lfuall keys / keys with a TTLfrequency, by Count-Min Sketch
allkeys-random / volatile-randomall keys / keys with a TTLrandom, from a seeded generator
volatile-ttlkeys with a TTLnearest deadline among the sampled keys

Recency uses CLOCK with a 2-bit reference counter kept in spare bits of the record header, so it costs no extra bytes per key. A read saturates the counter to 3, a write sets it to 1, and the eviction hand decrements it; a record at 0 is a victim. Reads earn more than writes, which lets the hand tell a read-hot set from write churn. Frequency uses a 4 × 2,048 Count-Min Sketch of one-byte Morris counters, 8 KiB per store, allocated only while an LFU policy is active and halved periodically so old popularity ages out. OBJECT FREQ reports that estimate; OBJECT IDLETIME is an honest 0, because there is no LRU clock. CLOCK is a sweep; the LFU, TTL and random policies examine maxmemory-samples candidates per step (5 by default). Eviction randomness comes from a seeded generator, so eviction replays exactly in the simulator.

Per-namespace budgets

A named memory namespace can carry its own budget and policy. Namespace DDL needs a node started with --data-dir.

127.0.0.1:6379> INF.NS CREATE sessions EVICTION allkeys-lru MAXMEMORY 512mb
OK
127.0.0.1:6379> INF.NS SET sessions MAXMEMORY 1gb
OK
127.0.0.1:6379> INF.NS SET sessions EVICTION inherit
OK
  • With its own MAXMEMORY, a namespace evicts only its own keys and never displaces another's. Its out-of-memory error is the same Redis text, scoped to connections using that namespace. Like maxmemory, the budget divides across cells.
  • Its bytes leave the node comparison. maxmemory bounds the pool: the numbered databases plus every namespace without a budget of its own. INFO memory reports that figure as used_memory_pool, so maxmemory − used_memory_pool is the headroom before eviction runs. used_memory counts every namespace and may sit above maxmemory.
  • EVICTION inherit follows maxmemory-policy; MAXMEMORY 0 or inherit removes the budget. Both keys reload without a restart.
  • Durable namespaces never evict, because evicting without logging a delete would bring the key back on replay. EVICTION is refused on them, and INF.NS SET refuses both keys. Tiered namespaces refuse both at creation too: MEM-BUDGET is their one budget.

Memory accounting

Every byte a cell holds is attributed, at the allocation site, to a named and counted domain. The arena counts requested bytes, mapped bytes and the slack between them, and the other structures count their own: the hash index, the TTL wheel, the eviction sketch, document tapes, arenas and caches, secondary-index trees, network buffers and connection state, and the reply and command pools.

SectionScopeFields
INFO memorywith --data-dir, the node summed over every cell (memory_scope:node); without one, the serving cell (memory_scope:cell)used_memory, used_memory_rss, process_rss, used_memory_pool, used_memory_doc_*, used_memory_idx_*

Mind the scope before you compare: multiply a cell-scope figure by the cell count before setting it against the process. process_rss sits beside the node fold for exactly that comparison.

The domains are reconciled against what the operating system reports. The project's exit-gate harness fails a run in which the sum of the domains drifts from process RSS beyond its tolerance, and the simulator checks memory accounting against its model at quiescence. An unattributed byte is a finding, not overhead. One pause is known and counted: growing the hash index doubles the table in one step on the write path, and index_grows in INFO stats counts each one.

Beyond eviction

Eviction is the right answer for a cache. When data must not be lost, use a durable namespace with a MEM-BUDGET instead: it answers pressure by demoting cold records to tier files on disk rather than deleting them, and reads them back through a suspending cold read. That works for string values today. See Beyond RAM.

L5
Memory is the product.

For a cache, memory per key is the cost of the product. Records carry an 8-byte header, the index slot is 8 bytes and holds no key, eviction bits live in spare header bits, and attribution against RSS is a gate, not a dashboard.
