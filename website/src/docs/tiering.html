The hybrid log

The design follows the hybrid log of Microsoft's FASTER. Each pair of a cell and a tiered namespace has a logical address space. Records are appended at increasing 48-bit addresses, and watermarks divide that space into regions:

RegionWhere it livesRule
Mutable tailRAMrecords are updated in place
Read-onlyRAM, then RAM and disk once flushednever changed; an update writes a new copy at the tail
Coldtier files on disk onlyread through a suspending cold read

The API enforces the read-only rule, because an in-place write there would diverge from a copy already on disk, and it releases RAM pages only below the flushed watermark. The index has the same shape as the in-memory index, but its address field holds a logical address. It keeps each entry's full 64-bit hash beside the table, so growing the table never reads a cold record.

Create a tiered namespace

Start the server with a data directory, then give a durable namespace a memory budget. MEM-BUDGET is what makes a namespace tiered; it applies only to MODE durable, and every other tier key is refused without it.

127.0.0.1:6379> INF.NS CREATE archive MODE durable FSYNC everysec MEM-BUDGET 1gb DISK-BUDGET 100gb
OK
127.0.0.1:6379> INF.NS USE archive
OK
127.0.0.1:6379> SET report:2026-10 "quarterly totals"
OK
127.0.0.1:6379> INF.NS SET archive MUTABLE-FRACTION 300
OK

INF.NS SET name KEY value changes any key except the two create-only ones; drop and recreate the namespace to change those. Sizes use Redis units: kb, mb and gb are powers of 1024. The budgets apply per cell: each cell enforces MEM-BUDGET and DISK-BUDGET on its own part of the namespace. MAXMEMORY and EVICTION are refused on a tiered namespace, because MEM-BUDGET is its one memory authority.

Demote, don't evict

A cache namespace answers memory pressure by evicting keys. A tiered namespace answers by demoting them, in three budgeted MAINTAIN steps: seal the mutable region down to its share of the budget, flush the sealed bytes to tier files, and release the RAM pages below the flushed watermark.

Tier files hold one contiguous address range each, in 4 KiB frames with a CRC32C apiece, so finding a byte is arithmetic. Each file keeps exact live and dead byte counts. Once a file is at least COMPACTION-DEAD-RATIO percent dead, compaction copies its live records forward to the tail a slice at a time and retires the file. Compaction only allocates space and never waits for it, so it cannot deadlock the flush it belongs to. Tier flush and compaction spend the cell's device budget, its share of the device model measured at first boot, alongside checkpoints and log zero-fill.

Cold reads suspend

When a lookup lands on a cold address, the store does no I/O. It returns the address as a candidate and the command suspends, so the cell keeps serving every other key it owns:

  • The read joins a bounded queue for its class, foreground or maintenance.
  • Once per iteration the queues drain into O_DIRECT reads, up to COLD-READ-QD in flight, three foreground reads for each maintenance read, with adjacent ranges of a file merged.
  • When the read completes, the command resumes, compares the full key and looks the key up again through the index, because anything may have changed while it waited.

A key read again soon after a cold read is promoted to the tail, so its next read is served from RAM; a key touched once by a sweep stays cold. CONFIG SET tiered-promote-on-read no turns promotion off.

Budgets and refusals

Every pressure point answers with a typed error:

ErrorWhen
DISKFULL tiered namespace disk budget exhausted (used=… budget=…)a write would place new tier bytes past DISK-BUDGET
DISKFULL tier device out of space (ENOSPC)the device is full
STALLED tiered write timed out waiting for flush progress (TAIL-STALL-TIMEOUT)a write waited longer than its timeout; retry it
BUSY cold-read queue saturated, try againthe cold-read queue is full

Recovery does not scan cold data. The MANIFEST names each tier file and how far it is durable, the checkpoint holds address references for records already in tier files, and the log tail replays on top. INFO tiering reports the address space, watermarks and budgets of the cell that served it.

What works today

Tiered namespaces serve the string family (GET, SET without expiry options, MGET, MSET, INCR and friends, APPEND, GETRANGE, SETRANGE, DEL, EXISTS), plus SCAN and DBSIZE. Multi-key commands resolve key by key.

Not yet

Tiered namespaces have no key expiry: the EXPIRE family and SET expiry options are refused, and TTL answers -1. JSON documents, other value types and secondary indexes on tiered namespaces arrive with documents beyond RAM, the last phase of M4.

Memory namespaces, the numbered databases and durable namespaces without a MEM-BUDGET have no hybrid log. A cell that is not durable runs none of this code; a durable cell runs the tiered maintenance step on every loop iteration, which reconciles its namespace set whether or not one is tiered.
